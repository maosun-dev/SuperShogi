# 計画8 強さの調整 作業手順書

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** CPU 同士を数百局戦わせ、強さの段階と札の強さを数字で確かめて直す。

**Architecture:** `tools/arena/arena.ts`（1組ぶんの対局を指して1局1行の JSON を書く）を `tools/arena/run.mjs` が7組同時に走らせ、`tools/arena/summary.mjs` が数える。CPU はアプリと同じ `chooseCpuAction` を使い、考える時間だけ短くする（`timeScale`、ふつう 0.1）。

**Spec:** `docs/superpowers/specs/2026-10-21-cards-cpu-handicap-design.md` の1章「うまくいった状態」と8章

## Global Constraints

- 目標：つよい→ふつう 8割以上、ふつう→よわい 8割以上、引き分け5%未満、どの札も入れた側の勝率 42〜58%
- 道具はアプリに入れない（`tools/` に置き、記録 `tools/arena/out/` は git に入れない）
- 時間を短くした対局で数えるので、強さの差はアプリより小さく出る見込み（つよいの読みが浅くなるため）

## Review Focus

1. 千日手の引き分けが多い → 読みの中で前の局面へ戻るのを損とする（計画7の追加で入れた）
2. 時間を短くしたことで、つよいとふつうの差が縮む → 差が出ないときは timeScale を上げて確かめ直す
3. 札の勝率は持ち込みがでたらめなので揺れる。1枚あたり100局以上で見る

## 結果（2026-10-22、timeScale 0.1、7組同時）

強さの段階（105局ずつ）

| 回 | つよい→ふつう | ふつう→よわい | つよい→よわい | 引き分け |
|---|---|---|---|---|
| 1回目（千日手の損60点） | 77.1%（引き分け7） | 100% | 100% | 6.7%（すべて千日手） |
| 千日手の損を150点に（つよい対ふつうだけ42局） | 95.2% | - | - | 0% |
| 時間切れの直しのあと | 85.7% | 100% | 100% | 2.9% |

札ごとの勝率（ふつう同士・でたらめな持ち込み・420局ずつ。1枚あたり130〜340局なので±4%ほど揺れる）

- 1回目：昇竜40.3%・凍てつく床41.2% が低い → 昇竜4→3、凍てつく床2→1
- 2回目：身代わり68.0%（1回目も58.2%）が高く、鋼の鎧37.8%（1回目45.7%）・王の盾40.9%（1回目44.4%）が低い → 身代わり3→4、鋼の鎧3→2、王の盾3→2
- 3回目：昇竜39.7% 以外は 43.5〜57.6%。昇竜は同じコストの2回目が51.7%なので、平均45.7%として直さない

ほかに見つけて直したこと：時間を短くしても1手15秒かかることがあった（根の最初の候補を読み終えるまで打ち切らなかったため）→ 時間の2倍で打ち切る。3回目は最大207ms（制限100ms）

## 残したこと

- よわいはふつう・つよいに1局も勝てない。人が相手なら勝てる強さのつもりだが、実機で遊んで確かめる
- 札の数字は CPU（ふつう）の使い方での強さ。人の使い方では変わりうる
