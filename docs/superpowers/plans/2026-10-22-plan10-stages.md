# 計画10：舞台（背景と画面の雰囲気）手順書

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 3つの舞台（歌舞伎・浮世絵・金屏風）を作って設定で選べるようにし、すべての画面の背景と色を明るく豪華にする。

**Architecture:** 層0（Blender で描いた絵3枚・全画面）・層1（2D キャンバスの動く飾り・全画面）・層2（盤の3Dに舞台ごとの床と光）・層3（文字とボタン。色は CSS 変数）。舞台は `<html data-stage>` と設定 `superShogi.settings` の `stage` で切り替える。

**Tech Stack:** TypeScript・Vite・Three.js・CSS 変数・Blender 4.5（`--background` の Python 台本）

**Spec:** `docs/superpowers/specs/2026-10-22-stages-design.md`

## Global Constraints

- 舞台の名前：`kabuki`（既定）・`ukiyoe`・`byobu`。背景の動き：`full`・`low`
- 札の色（藍・紅・金箔）と盤・駒の色は変えない
- 絵は `public/stages/<舞台>/back.webp`・`mid.webp`・`front.webp`・`thumb.webp`。1舞台あたり 1.5MB 以内が目安
- 動く飾りの粒は 1 フレーム 120 個まで。`low` では描かない
- 文字と地の明るさの差は 4.5:1 以上（普通の文字）
- 見た目に触る Task は frontend-design の考え方に沿う（読み込み済み）。絵は自作
- コメント・コミットは日本語。最後に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. 保存された設定に知らない舞台名 → 既定（kabuki）に戻り、画面が真っ白にならない（Task 1 にテスト）
2. 絵のファイルが読めない（オフライン・壊れた） → 色の決まりのグラデーションだけで画面が成り立つ（Task 4 で地の色を敷く）
3. 舞台を切り替えたとき、前の舞台の飾り・床・光が残らない（Task 5・6 で片付けを確かめる）
4. 結果画面の暗幕（`.stage-host.dim`）・演出の暗転は、明るい舞台でも効く（Task 2 で色を差し替える）
5. 横長の画面（パソコン）でも絵が切れて変にならない（`object-fit: cover` 相当で中央合わせ）

### Task 1: 設定に舞台と背景の動きを足す

**Files:** Modify `src/app/storage.ts`（`Settings` に `stage: StageId; motion: 'full' | 'low'`、`DEFAULT_SETTINGS`、読み込みの丸め）／Create `src/app/stageTheme.ts`（`STAGES: StageId[]`・`STAGE_LABEL`・`applyStage(doc, settings)` が `data-stage` と `data-motion` を付ける）／Test `tests/app/storage.test.ts`・`tests/app/stageTheme.test.ts`

- [ ] テスト：既定は `stage:'kabuki'`、`motion` は既定で `'full'`（動きを減らす端末の判定は `applyStage` 側）。知らない舞台名・壊れた値は既定。`applyStage` が `data-stage`・`data-motion` を付ける（動きを減らす端末なら `low`）
- [ ] 落ちるのを見る → 実装 → 通るのを見る → コミット「設定に舞台と背景の動きを足す」

### Task 2: 色の決まりを舞台ごとの変数にする

**Files:** Modify `src/app/style.css`（`:root` に `--ground`・`--paper`・`--ink`・`--ink-soft`・`--line`・`--accent` と、`[data-stage=...]` ごとの値。`body` の背景、文字色 `--gofun` を使っている地の文字を `--ink` へ）／Modify `src/app/main.ts`（起動時に `applyStage`）

- [ ] 全画面（タイトル・強さ選び・札選び・図鑑・設定・対局・結果）を開発用サーバーで3舞台とも開き、文字が読めるか撮って確かめる。明るさの差を計算で確かめる
- [ ] コミット「色の決まりを舞台ごとに差し替えられるようにする」

### Task 3: Blender で舞台の絵を描く台本

**Files:** Create `tools/stage/build.py`（舞台ごとに形・質感・墨の輪郭線を組み立て、3層と見本を WebP で書き出す）・`tools/stage/README.md`（流し方）／出力 `public/stages/*`

- [ ] 1枚だけ小さく描き出して、Blender が裏で動くこと（Cycles・Freestyle・WebP）を確かめる
- [ ] 3舞台 × 4枚を書き出し、絵を見て直す。大きさの目安を確かめる
- [ ] コミット「Blender の台本で3つの舞台の絵を描く」

### Task 4: 層0：背景の絵を全画面に重ねる

**Files:** Create `src/view/backdrop.ts`（`mountBackdrop(root): { setStage(id), setMotion(m), destroy() }`。3枚の `<img>` を重ね、傾き・指・時間で少しずらす）／Modify `src/app/main.ts`・`style.css`

- [ ] 絵が読めないときは地のグラデーションだけになることを確かめる
- [ ] 開発用サーバーで3舞台を撮る → コミット「背景の絵を3層で重ねる」

### Task 5: 層1：動く飾り

**Files:** Create `src/view/ambient.ts`（全画面の 2D キャンバス。舞台ごとの粒。`low` で止める。粒は 120 個まで）／Test `tests/view/ambient.test.ts`（粒の数の上限と、舞台を替えると前の粒が消えること。キャンバスを使わない計算の部分）

- [ ] テスト → 実装 → 撮る → コミット「舞台ごとの動く飾りを足す」

### Task 6: 層2：盤の床と光

**Files:** Modify `src/view/stage.ts`（`setStageLook(id)`：半球光・日の光の色、床の板を差し替え）／Create `src/view/stageFloor.ts`（舞台ごとの床と光だまり）／`style.css`（`.stage-host` の縁をぼかす `mask-image`）

- [ ] 舞台を替えて前の床が消える（片付け）ことを確かめる → 撮る → コミット「盤の下に舞台ごとの床と光を置く」

### Task 7: 設定の画面で選ぶ

**Files:** Modify `src/app/screens/settings.ts`（見本の絵を3つ並べて選ぶ。背景の動き 多め／少なめ）・`style.css`

- [ ] 選ぶとその場で背景が替わり、保存される → 撮る → コミット「設定の画面で舞台を選べるようにする」
