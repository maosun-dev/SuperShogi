# 計画7 CPU 強化 作業手順書

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CPU が王を取りに来て、王を守り、札を狙って使うようにする。「つよい」でも1手3秒以内。

**Architecture:** 今の先読み（ネガマックス＋アルファベータ＋駒を取る手の延長読み、`src/ai/search.ts`）を土台に、局面の点数（`src/ai/evaluate.ts`）へ王の守りと迫りを足し、読みを速くし（局面の複製を手書きに、読んだ局面を覚える、良い手から読む）、札の候補を札ごとの目安で絞る（`src/ai/cardHints.ts`）。強さの段階は `src/ai/levels.ts`。

**Tech Stack:** TypeScript・Vitest

**Spec:** `docs/superpowers/specs/2026-10-21-cards-cpu-handicap-design.md` の6章

## 計ってわかったこと（作る前）

- 1手を当てるのに約50µs、そのうち局面の複製（JSON）が約27µs
- 初期局面で札の行動が79個あり、浅い所では全部を当ててから絞っていた（1局面あたり約4ms）
- 「つよい」は初期局面で深さ4・約8千局面／1.2秒

## Global Constraints

- CPU は見えている局面（`viewFor`）だけで考える。相手の伏せた札の中身と場所は使わない
- 「つよい」でも1手 `timeLimitMs` 3000 以内（今の時間のテストを通したまま）
- 同じ局面・同じ種なら同じ手（今の決めごと）
- ルール本体（`src/rules`）は CPU のための近道を持たない。速くするのは複製だけ

## Review Focus

1. 王手をかけられている側の延長読みで、駒を取る手しか見ないと「逃げられるのに負け」と読む → 王手のときは逃げる手も読む（Task 3 のテスト）
2. 1手で王を取れる局面では、どの強さでも取る（Task 3 のテスト）
3. 王を取られる手を放っておかない：1手で王を取られる局面では、ふつう以上は逃げるか守る（Task 3 のテスト）
4. 札の候補を絞りすぎて、効く札（王手を消す入れ替え・相手の竜への格落とし）を見落とさない（Task 4 のテスト）
5. 局面を覚える表は対局ごと（search ごと）に作り直す。前の対局の点数を使わない

### Task 2: 局面の点数
**Files:** `src/ai/evaluate.ts`、テスト `tests/ai/evaluate.test.ts`
- 王の守り：王の隣8マスの味方1つにつき `KING_GUARD`、相手が利いている隣のマス1つにつき `-KING_DANGER`
- 王への迫り：相手の王の周り（隣8マス）に自分の駒が利いているマス1つにつき `ATTACK`、持ち駒がある側は `HAND_ATTACK` を足す
- 凍った駒は残りの手番1つにつき駒の点数の15%引く。成れない飛車・角は `-150`、ほかの成れない駒は `-40`
- 纏札の点数：貫きの槍 300、重りの枷は付けられた駒の持ち主から見て `-(駒の点数×0.4、最低150)`
- [ ] テスト：王の隣に金がいる方が高い／相手の王の周りに利きが多い方が高い／凍った駒・成れない飛車は低い／重りの枷は付けられた側に損
- [ ] 作って通し、コミット

### Task 3: 読みを速く・深く
**Files:** `src/ai/search.ts`、テスト `tests/ai/search.test.ts`
- 読んだ局面を覚える表（キーは `positionKey`、深さ・点数・上限下限・いちばん良かった手）
- 良い手から読む：表の手 → 駒を取る手（価値の大きい駒を、安い駒で）→ 前に枝を切った手（キラー手、深さごとに2つ）→ 成る手 → ほか
- 深さ0になった子が王手をかけられていたら、1手延長する（延長は根から `maxDepth + 2` まで）
- 延長読みで王手をかけられている側は、取る手だけでなく、すべての動かす手・打つ手を読む
- [ ] テスト：1手で王を取れるなら取る／王手を逃げる手があるのに負けと読まない／1手詰め（打って王手、逃げ場なし）を見つける（深さ3）
- [ ] 作って通し、初期局面での局面数と深さを計り、コミット

### Task 4: 札の候補を絞る
**Files:** Create `src/ai/cardHints.ts`、Modify `src/ai/search.ts`、テスト `tests/ai/cardHints.test.ts`
**Interfaces:** `cardHints(s: GameState, actions: Action[]): Action[]` — 札の行動のうち、使う価値のありそうなものだけを返す（駒の行動は返さない）
- 押し返しの風・落雷：相手の駒の点数の大きい順に3つ
- 入れ替えの術：自分の王を含む組（王手をかけられているときだけ）と、飛・角を含む組から最大6つ
- 呼び戻し：全部（7つまで）
- 格落とし：全部（相手の成り駒は少ない）
- 昇竜：飛・角と、成って得の大きい駒から3つ
- 落とし穴・凍てつく床：相手の王以外の駒が動けるマスのうち、自分の王に近い順に4つ
- 盤の横の忍札：1つ（身代わりは自分の王の隣に味方がいるときだけ）
- 纏札：自分の駒の点数の大きい順に3つ（鋼の鎧・王の盾は王の隣の駒も入れる）。重りの枷は相手の駒の点数の大きい順に3つ
- [ ] テスト：札ごとの数の上限、王手のときの入れ替えに王の組が入る、相手の竜への格落としが入る
- [ ] `cardCandidates` の前にかけ、時間のテストを通してコミット

### Task 5: 強さの段階

- [ ] テスト：持ち込みが通る・強い方が深い・よわいはときどき乱れる（種を変えて手がばらつく）
