# 超将棋 計画2：CPU 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 「見えている局面」だけを受け取り、駒の手とカードの使い方の両方から1手を選んで返す CPU を作る。強さは3段階。裏側のスレッド（Web Worker）から呼べる形にする。

**Architecture:** 局面の点数を付ける `evaluate`、先を読む `search`（アルファベータ法＝見込みのない枝を途中で打ち切る読み方。時間切れで止まる「反復深化」＝浅い読みから順に深くする方式）、強さごとの設定 `levels`、Worker とのやり取り（`protocol` / `worker` / `client`）に分ける。読みの中ではルールの部品の `applyAction` から合法手の確認を省いた版を使って速くする。

**Tech Stack:** TypeScript 5 / Vitest 3（計画1と同じ。Vite と Worker の実際の起動は計画3）

**Spec:** `docs/superpowers/specs/2026-10-20-super-shogi-design.md`（特に 2.2・2.6・5.1「CPU の部品」・6「CPU」）

**この計画のあと：** 計画3＝画面と演出（ここで `new Worker(...)` を作って `createCpuClient` に渡す）、計画4＝iPhone アプリ化

**実装後の変更（最終点検で決定）：** 手番の取り違えを防ぐため、`search(view, side, opts)`・`chooseCpuAction(view, side, level, seed)`・`ThinkRequest.side`・`CpuClient.think(view, side, level, seed)` と「どちらの側として考えるか」を渡す形にした。`view.turn !== side` なら `'CPU の手番ではありません'` を投げる。カード候補は「同点なら対象の駒の価値が高い順」「1枚のカードから最大3候補（`CARD_CANDIDATES_PER_CARD`）」で絞る。深さ1も、根の候補を1つ読み終えたあとなら時間切れで止まる。

## Global Constraints

- CPU は「見えている情報」だけで考える。入力は必ず `viewFor(本当の局面, CPU の側)` の結果。本当の局面を CPU の部品に渡す口を作らない
- CPU が返す行動は、本当の局面でも合法であること（`applyAction` が例外を出さない）
- 強さは3段階：`'weak'`（弱い）・`'normal'`（ふつう）・`'strong'`（強い）。違いは「読む深さ」と「わざと迷う度合い（点数に混ぜるゆらぎ）」
- CPU の持ち込みカードも合計コスト10以内・同じカードは2枚まで（`validateDeck` を通る）
- 決まった時間内に答える：各強さの `timeLimitMs` ＋ 200ms 以内
- `src/ai` は DOM・Three.js に依存しない。tsconfig の `lib` は `ES2022` のまま（Worker 用の型は自前の最小の型で済ませる）。時刻は `Date.now()`
- 乱数は種（シード）付き。同じ局面・同じ種なら同じ手を返す（テストのため）
- コードのコメントとコミットメッセージは日本語。コミットの末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **伏せた相手の罠がある局面**：`viewFor` で `cardId`・`at` が `null` の罠が混ざっていても、読みが落ちず、返す手が本当の局面で合法であること → タスク3にテストを足す
2. **自分の王を取られる手を避ける**：ふつう以上では、取れる駒に目がくらんで王の前の駒をどけ、次に王を取られる手を選ばないこと → タスク3にテストを足す
3. **駒が多く、手の数が膨らむ局面**（持ち駒が多い・入れ替えの術の組が多い・韋駄天の2回目）でも時間内に答えること → タスク4にテストを足す
4. **対局が終わった局面・手番でない側として呼ばれる**：黙って変な手を返さず、分かる言葉の例外を出すこと → タスク3にテストを足す
5. **CPU 同士で長く指し続ける**：途中で反則の行動を出さない・例外を出さないこと → タスク4にテストを足す

### Task 3: 先読み

**Files:**
- Create: `src/ai/search.ts`
- Test: `tests/ai/search.test.ts`

**Interfaces:**
- Consumes: `legalActions`, `applyActionUnchecked`, `evaluate`, `makeRng`, `idx`, `PIECE_VALUE`
- Produces:
  ```ts
  export interface SearchOptions {
    maxDepth: number;      // 読む深さの上限（手番1回＝1）
    timeLimitMs: number;   // これを過ぎたら、読み終えたいちばん深い結果を返す
    qDepth: number;        // 深さ0のあと、駒を取る手だけで延長して読む回数
    cardPlies: number;     // 根から何手目までカードの行動を候補に入れるか
    cardWidth: number;     // 候補に入れるカードの行動の数の上限
    noise: number;         // 末端の点数に混ぜるゆらぎの幅（±noise）
    seed: number;
    now?: () => number;    // 既定は Date.now（テストで差し替える）
  }
  export interface SearchResult { action: Action; score: number; depth: number; nodes: number }
  export function search(view: GameState, opts: SearchOptions): SearchResult;
  export const WIN = 1_000_000;
  ```

**決めごと（テストだけでは決まらない部分）：**
- 入口：`view.result` があれば `Error('対局はもう終わっています')`、`legalActions(view)` が空なら `Error('指せる行動がありません')`。読みは `{ ...view, seen: {} }` から始める（千日手の記録を毎回複製すると遅いため。読みの中では千日手を考えない）。候補が1つならすぐ返す
- 点数はつねに「その局面の手番の側」から見る（ネガマックス）。子の局面の手番が親と同じ（王を取って終局・相手が指せず手番が戻った）ときは符号を変えず窓もそのまま、違うときは `-search(child, -beta, -alpha)`
- 終局：`winner === null` は0、`winner === 手番` は `WIN - 根からの手数`、それ以外は `-(WIN - 根からの手数)`（早く勝つ・遅く負ける手を選ぶため）
- 候補：`legalActions` から作る。根からの手数が `cardPlies` 未満なら、カードの行動を「適用した直後の `evaluate`（使った側から見た点数）」の高い順に `cardWidth` 個だけ残す。それより深いところではカードの行動を入れない
- 並べ替え：①前の深さで一番だった手（根だけ）②駒を取る手（取られる駒の価値の大きい順、同じなら動かす駒の価値の小さい順）③成る手 ④カード ⑤それ以外
- 延長読み（深さ0）：「そのまま止まる」点数（`evaluate`＋ゆらぎ）を下限にして、相手の駒のマスへ動く手（`second` なし）だけを `qDepth` 回まで読む。凍てつく盤の側は `legalActions` が取る手を出さないので、そのまま正しく扱われる
- ゆらぎ：末端の点数に `(rng() * 2 - 1) * noise` を足す。`rng = makeRng(opts.seed)`
- 時間：深さ1から `maxDepth` まで順に読む。256局面ごとに `now()` を見て、`timeLimitMs` を過ぎたら読みを打ち切り、最後まで読めた深さの手を返す。深さ1は時間切れでも最後まで読む（必ず手を返すため）

- [ ] **Step 1: 失敗するテストを書く**（局面は `emptyState` / `put` / `giveCard` で作る。既定の設定 `BASE = { maxDepth: 2, timeLimitMs: 5000, qDepth: 4, cardPlies: 1, cardWidth: 8, noise: 0, seed: 1 }`）

- `取れる王は取る`：先手番、後手の王 (4,1)、先手の金 (4,2)、先手の王 (4,8) → `action` が `{ type:'move', from:{c:4,r:2}, to:{c:4,r:1} }`、`score >= WIN - 1`
- `ただで取れる飛車を取る`：後手の飛車 (2,4) を先手の銀 (2,5) が取れて、取り返されない → 取る手。`maxDepth: 1` でも同じ
- `王の前の駒をどけない`：先手の王 (4,8)、先手の金 (4,5)、後手の飛車 (4,0)、後手の歩 (3,4)（金で取れる）、後手の王 (8,0) → `from` が (4,5) でない
