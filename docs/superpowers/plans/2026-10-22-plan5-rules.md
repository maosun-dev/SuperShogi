# 計画5 ルール（札18種類・忍札の手番・駒ごとの凍結/成れない・駒落ち）作業手順書

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 設計書のルール（3章・4章・5章）をルール本体に入れ、今のアプリが型チェックとテストを通ったまま動く状態にする。

**Architecture:** ルール本体（`src/rules`）と札の定義（`src/cards`）を直す。状態は駒1つずつに `frozen`（残りの手番）と `sealed`（成れない）を持たせ、局面全体の `frozen: Side` は消す。見た目（`src/view`・`src/fx`）とアプリ（`src/app`）は、型が通って今の演出が壊れない最小限だけ直す（本格的な絵と演出は計画6）。

**Tech Stack:** TypeScript・Vitest

**Spec:** `docs/superpowers/specs/2026-10-21-cards-cpu-handicap-design.md`

## Global Constraints

- プログラムの中の種類名 `magic` / `trap` / `equip` は変えない
- 札は全18種類。コスト上限10・同じ札2枚まで・伏せられる忍札は1人3枚までは変えない
- 新しい札の id：格落とし `kakuotoshi`・昇竜 `shoryu`・相討ち `aiuchi`・身代わり `migawari`・貫きの槍 `tsuranuki`・重りの枷 `omori`。凍てつく床は今の id `itetsuku` を使い回す（種類を trap に変える。保存した持ち込みが壊れない）
- 「いちばん安い駒」は `PIECE_VALUE`（成り駒は `PROMOTED_VALUE`）で決め、同じ点数なら盤の順（`board` の添字が小さい方）
- ルール本体は `src/ai` を読み込まない（`PIECE_VALUE` と `PROMOTED_VALUE` は `src/rules/values.ts` へ移し、`src/ai/evaluate.ts` はそこから読み込んで export し直す）
- `npm.cmd test` と `npm.cmd run typecheck` がどちらも通ったままにする

## Review Focus

1. 忍札を伏せたあと、行える行動が1つもない → 手番が相手へ回る（`passed`）。Task 2 のテストで押さえる
2. 韋駄天の1回目で凍てつく床に入った駒 → 2回目は飛ばす。Task 4 のテストで押さえる
3. 成れない歩・香・桂は、成らないと行き所がないマスへは動けない（手が出ない）。Task 4 のテストで押さえる
4. 相手が凍てつく床へ押し返しの風で押し込んだ駒は、持ち主の次の手番から2手番動けない（自分で入ったときと数がずれない）。Task 4
5. 駒落ちで CPU 側（後手）が先に指すとき、対局を始めた直後に CPU が1手指して人間の手番になる。Task 8

### Task 4: 凍てつく床（凍結の数え方）

**Files:** Modify `src/cards/magic.ts`（凍てつく盤を消す）, `src/cards/trap.ts`, `src/rules/game.ts`；Test `tests/rules/cards-trap.test.ts`

- 凍てつく床：trap・コスト2・`placement: 'square'`・`trigger: 'enter'`。入った駒を凍らせる。王は1、王以外は2
- 凍らせるとき、その駒の持ち主が今の手番なら `turns + 1` を入れる（その手番の終わりの1減りで `turns` になる）。出来事の `turns` は本来の数（1 か 2）
- 王が入ったとき：落とし穴は発動しないが凍てつく床は発動する。同じマスに相手の札が2枚あれば、王なら落とし穴を除いた中で uid が小さい1枚
- 入れ替えの術は凍った自分の駒を選べない（凍った駒は動けない）
- [x] テスト：自分で入った駒は次の自分の手番から2手番動けず3手番目に動ける／王は1手番／押し返しの風で押し込まれた駒も同じ数／韋駄天の1回目で入ったら2回目は飛ばす／成れない歩は最奥段へ動く手が出ない
- [x] 作って通ることを確かめ、コミット

### Task 5: 新しい術札（格落とし・昇竜）

- [x] テスト：格落としの対象（成り駒だけ・二歩になる歩は選べない・王の盾の隣は選べない）と効果、纏札が残る／昇竜で成る・成り封じで止まり sealed になる・鏡の結界が先に打ち消す（成り封じは残る）

### Task 8: 駒落ち

**Files:** Modify `src/rules/types.ts`, `src/rules/board.ts`, `src/rules/game.ts`, `src/app/match.ts`；Test `tests/rules/game.test.ts`, `tests/app/match.test.ts`

**Interfaces:**
- `export type HandicapKind = 'none' | 'kyo' | 'kaku' | 'hisha' | 'hikyo' | 'nimai' | 'yonmai' | 'rokumai'`
- `export interface Handicap { side: Side; kind: HandicapKind }`
- `createGame(decks, opts?: { handicap?: Handicap })`。`kind !== 'none'` なら `turn` は `handicap.side`
- `HANDICAP_LABEL: Record<HandicapKind, string>`（なし・香落ち・角落ち・飛車落ち・飛香落ち・二枚落ち・四枚落ち・六枚落ち）
- `createMatch` の opts に `handicap?: Handicap`。`start()` は CPU の手番なら CPU に指させて、人間の手番まで進める
- 落とす駒：先手の左の香は (0,8)、後手の左の香は (8,0)。角は先手 (1,7)・後手 (7,1)、飛車は先手 (7,7)・後手 (1,1)。四枚落ちは両方の香、六枚落ちはさらに両方の桂

- [x] テスト：各駒落ちで盤から消える駒の数と場所・先に指す側・`none` は今と同じ／match：CPU 側に駒落ちを付けると `start()` のあと人間の手番で、presenter が1回呼ばれている
- [x] 作って通ることを確かめ、コミット
