# 友と対局（近くの iPhone 2台で対戦）設計書

2026-10-25 ユーザーと決めた内容。

## 1. 狙い

- 目の前にいる友だちと、iPhone 2台で超将棋を指せるようにする
- ネットも Wi-Fi のルーターもいらない。Android とはつながない
- 友だち同士の遊びなので、札の中身を盗み見るようなズルへの備えはしない
- うまくいった、と言える状態：片方が「誘う」、もう片方が「探す」を押すとすぐつながり、指した手や使った札が相手の画面でも同じ演出で流れ、最後まで対局できる。切れてもつなぎ直して続きから指せる

## 2. 通信の方式

- Apple の近距離通信（MultipeerConnectivity）を使う。Bluetooth と、ルーターなしの Wi-Fi 直接通信（2台が同じ Wi-Fi にいればその Wi-Fi）を iOS が自動で使い分ける。アカウントもログインもいらない
- 届く距離の目安：Bluetooth だけなら約10m、Wi-Fi 直接通信なら見通しがよければ数十m
- Swift で小さな Capacitor の部品（以下「近距離の部品」）を書き、アプリに入れる。決まりごとは全部 TypeScript 側に置き、部品は運ぶだけ
- 見送った案：Game Center（2人ともログインが要る）、Bluetooth だけの既成の部品（探す側専用で iPhone 同士がつながらない）

## 3. 画面の流れ

1. タイトルの千社札に3枚目「**友と対局**」を足す
2. **つなぐ画面**（新しい画面 `link`）：大きな札「誘う」「探す」
   - 誘う：合言葉（駒の名前＋漢数字。例「桂馬の三」）を出して待つ。来た相手はそのまま受け入れる
   - 探す：近くで誘っている人の合言葉を並べる。押すとつながる
   - はじめての時に iOS が「ローカルネットワーク上の機器を探してよいか」をたずねる（Apple の決まり）。断られたときは「設定アプリの 超将棋 → ローカルネットワーク をオンにしてください」と出す
   - 戻るでタイトルへ。つながりも切る
3. **札選び**：いつもの札選びの画面で、それぞれ自分の札を選ぶ。駒落ちの欄は誘った側にだけ出す。「次へ」で相手を待つ（「相手が札を選んでいます」）
4. **くじ**：両方そろったら誘った側がくじで先手を決めて送る。朱の判が「先」か「後」をポンと押す短い演出（約1秒）。駒落ちがあるときは将棋の決まりどおり落とした側が先手で、くじは引かない
5. **札見せ**：いつもの札見せ（相手の札は「友」の札として見せる）
6. **対局**：自分はいつも盤の手前。相手の手は CPU の手と同じ演出で流れる。上の帯は「CPU・弱い」の代わりに「友」。投了できる。下の駒台に「待った」の判（5章）
7. **結果画面**：いつもの筆文字と幕。ボタンは「**もう一度**」（同じ相手と札選びから。相手が押すまで「相手を待っています」）と「**タイトルへ**」（つながりを切る）
   - 友との対局は戦績に数えない（稽古と同じ）。持ち込み札はいつもどおり保存する
   - 広告は今と同じく対局の外の画面だけ

## 4. 盤面のそろえ方

### 4.1 盤面は1つ、見る向きだけ回す

- 本当の盤面は2台とも同じものを持つ。誘った側＝先手の席（`sente`）、探した側＝後手の席（`gote`）。先に指すのは4章のくじ・駒落ちで決まった側（`createGame` の手番の初期値を渡せるようにする）
- 探した側の iPhone では、見せる盤面・合法手・出来事を **180度回して先手と後手を入れ替える**（`mirror`）。マスは `{c, r} → {8-c, 8-r}`、`Side` は入れ替え。駒の id・札の uid は変えない
- 自分の操作（`Action`）はもう一度 `mirror` して本当の盤面に当てはめる（`mirror` は2回で元に戻る）
- 合法手は「本当の盤面を自分の席から見た形（`viewFor(real, 自分の席)`）で `legalActions` → `mirror`」で作る。回した盤面で `legalActions` を直接呼ばない（千日手の記録 `seen` は回さないため）
- 演出・駒台・HUD は今までどおり「自分＝先手・手前」のまま動く。友との対局で演出の作りは変えない

### 4.2 対局の進行役

- 今の `createMatch`（`src/app/match.ts`）は相手を `CpuClient` として持つ。相手を「次の手をくれるもの」（`Opponent`）に広げ、CPU と友の2つを用意する
  - `cpuOpponent`：今の CPU（中身は今のまま）
  - `friendOpponent`：相手の iPhone から届いた手を待って返す
- 自分の席（`me: Side`）を `createMatch` に渡せるようにする。CPU 対戦は今までどおり `sente`
- 見せる側（`view`・`legal`・`Step`）は `me` が `gote` のとき `mirror` を通す
- 自分が指した手は相手へ送る（送ってから自分の演出を流す）

### 4.3 送るもの（`src/net/protocol.ts`）

すべて JSON。手には何手目かの番号 `n`（記録の長さ）を付ける。

| 種類 | 中身 | いつ |
|---|---|---|
| `hello` | アプリの版・対局の番号（無ければ null） | つながった直後・つなぎ直した直後 |
| `ready` | 自分の持ち込み札・（誘った側だけ）駒落ち | 札選びで「次へ」 |
| `start` | 対局の番号・先手の席・両者の札・駒落ち | 誘った側が両方の `ready` を受けたら |
| `act` | `n`・本当の盤面の向きの `Action`・当てはめたあとの指紋 | 指したとき |
| `resign` | `n` | 投了 |
| `matta` / `mattaReply` / `mattaCancel` | 戻す先の記録の長さ `to`／受けるか | 待った（5章） |
| `sync` | 持っている記録の長さ `n` | つなぎ直したあと |
| `log` | 記録の `from` 以降の手 | 相手の記録が短いとき |
| `quit` | — | 「やめる」・タイトルへ |
| `again` | — | 結果画面の「もう一度」 |

- **版**：アプリの版（`MARKETING_VERSION`。組み立てのときに Vite で埋め込む）が違えば「同じ版にそろえてください」と出してつながない
- **対局の番号**：`start` のときに誘った側がでたらめに作る。つなぎ直した時に番号が合わなければ続きとみなさない
- **指紋**：本当の盤面を決まった順で文字にしてから作る短い数字（32ビットの FNV-1a で足りる）。受け取った手を当てはめた結果と食い違ったら「盤面が合わなくなりました」と出して対局を終える（本来は起きない安全装置。戦績に数えない）
- ルールにでたらめは無いので、同じ記録を同じ順に当てはめれば2台は必ず同じ盤面になる

### 4.4 記録

- 対局の中身は「最初の盤面を作る材料（札・駒落ち・先手）」と「手の記録（`Action[]`）」だけ。iPhone に保存しない（アプリが開いている間だけ）
- 盤面は記録から作り直せる（待った・つなぎ直しで使う）

## 5. 待った（友との対局だけ）

- 戻すのは **自分の最後の手番**。1手番に操作が何回かある時（忍札を伏せてから指す・押し返しの風の続きの手）は、その手番の操作をまとめて戻す。つまり「最後に自分の手番が始まった時点の記録の長さ」まで戻す
- 相手がもう指していたら、相手の手も一緒に戻る（自分の番に戻る）
- 自分がまだ一度も指していない時と、決着のあとは押せない（判を薄くする）
- 回数の上限はなし。相手は毎回「受ける」「断る」を選べる
- 流れ
  1. 自分が「待った」→ `matta {to}` を送る。自分の画面に「待ったを求めています」＋「取り消す」
  2. 相手の画面に和紙の短冊「待ったを求められています　受ける／断る」。返事をするまで相手は指せない（演出中なら演出のあとに出す）
  3. 受けた → `mattaReply {ok:true, to}`。2台とも記録を `to` まで切り、盤面を作り直す。拍子木を一度鳴らし、盤を描き直す（`sync`）
  4. 断った → 「断られました」と出して続き
- 行き違い：自分の `matta` を送ったあとに相手の手が届いたら、その手はふつうに当てはめて演出する。受けられたら `to` まで戻すので、届いた手も消える。2台とも同じ `to` で切るのでずれない
- 割り切り：戻しても、相手が一度見たこと（発動して見えた忍札の場所など）は消えない

## 6. 切れたとき・片付け

- 切れたら2台とも「つなぎ直しています」と「やめる」を出す（演出の途中なら演出のあと）。指す操作はできない
- 裏で自動でつなぎ直す：誘った側は同じ合言葉で誘い直し、探した側は同じ相手（部品が覚えている相手の名前）を見つけたら自動でつなぐ
- つながったら `hello` で版と対局の番号を確かめ、`sync` で記録の長さを見せ合う。短い側に `log` で足りない手を送り、演出なしで盤面を作り直して続きから
- 対局の中身が消える時（2台とも）
  - 決着・投了：結果画面へ進んだ時点で消える（「もう一度」のためにつながりは残す。「タイトルへ」で切る）
  - 「やめる」：すぐ消え、`quit` を送る。届けば相手に「相手が対局をやめました」と出て相手の対局も消える
  - `quit` が届かなかった・アプリを閉じた：あとでつながった時に相手の `hello` の対局の番号が無い（または違う）ので、待っていた側に「相手が対局をやめました」と出て消える。待っている側が自分で「やめる」を押しても消える
- 消えないもの：持ち込み札（いつもどおり保存）
- アプリが裏へ回ると iOS がつながりを切ることがある。戻ってきたら上の流れでつなぎ直す

## 7. 近距離の部品（Swift）

- 置き場所：`ios/App/App/NearbyPlugin.swift`。Capacitor の `CAPBridgeViewController` を受け継いだ画面（`MainViewController.swift`、Main.storyboard の customClass を差し替える）の `capacitorDidLoad` で登録する
- サービスの名前は `super-shogi`（15字以内・英小文字とハイフン）。Info.plist に `NSLocalNetworkUsageDescription`（「近くの友だちと対局するために、近くの iPhone を探します」）と `NSBonjourServices`（`_super-shogi._tcp`・`_super-shogi._udp`）を足す
- できること（JS から呼ぶ）

| 名前 | 中身 |
|---|---|
| `host({ name })` | 合言葉 `name` で誘い始める。来た相手は受け入れる（1人だけ） |
| `browse()` | 探し始める |
| `join({ peer })` | 一覧の相手につなぐ |
| `send({ data })` | 文字を確実に（順番どおり）送る |
| `stop()` | 誘う・探す・つながりを全部やめる |

- 知らせ（JS へ）：`found {peer, name}`・`lost {peer}`・`connected {peer, name}`・`disconnected {peer}`・`message {data}`
- つなぎ直しの判断は JS 側でする（部品は言われたとおり誘う・探す・つなぐだけ）

## 8. TypeScript 側の部品

| ファイル | 役目 |
|---|---|
| `src/net/mirror.ts` | 盤面・手・出来事を180度回す（`mirrorState`・`mirrorAction`・`mirrorEvents`） |
| `src/net/protocol.ts` | 送るものの型と、受け取ったものの形の確かめ |
| `src/net/fingerprint.ts` | 盤面の指紋 |
| `src/net/link.ts` | 通信の窓口の型 `Link`（送る・知らせを受ける・つなぐ・やめる）。近距離の部品版と、開発用のにせ版（同じパソコンのタブ2枚を `BroadcastChannel` でつなぐ）と、テスト用の対の版 |
| `src/net/session.ts` | つながり〜札選び〜くじ〜対局〜待った〜つなぎ直し〜片付けの流れ（DOM なし。テストで全部たどれる） |
| `src/app/match.ts` | 相手を `Opponent` に広げ、`me` と `mirror` を通す |
| `src/app/screens/link.ts` | つなぐ画面 |
| 既存の画面 | タイトル（3枚目の札）・札選び（友モード：駒落ちは誘った側だけ・相手待ち）・札見せ・対局（「友」・待ったの判・短冊・つなぎ直し）・結果（友モードのボタン） |

## 9. 確かめ方

- テスト
  - `mirror`：手・出来事の全種類と盤面で、2回回すと元どおり。回した盤面の駒が手前と奥で入れ替わる
  - 1台の中で2台ぶんの session を対の `Link` でつなぎ、でたらめな手で最後まで指して、2台の盤面と指紋がいつも同じ
  - 切れる → つなぎ直す → `log` で送り直す。対局の番号が違えば続きとみなさない。版が違えばつながない
  - 待った：受ける・断る・取り消す・相手がもう指していた・行き違い
  - やめる・決着・`quit` が届かなかった時に、2台とも対局の中身が消える
- ブラウザ（開発中だけ）：`?link=fake` でにせの通信を使い、タブ2枚で画面の流れ・演出・待った・つなぎ直し（切断のふりのボタン）を目で見る
- 実機：TestFlight を手元の iPhone 2台（または iPhone と iPad。iPad では iPhone 用の画面のまま動く）に入れ、つながるまでの速さ・届く距離・片方をスリープにした時のつなぎ直しを見てもらう

## 10. 作らないもの

- 観戦・3人以上
- 持ち時間（時計）
- 対局の保存と再開（アプリを閉じたら消える）
